# 工具拦截后的撤销记录与文件链接转义

开场说明/任务规则属于工具准入，必须先于文件 checkpoint 的 before 快照。被准入钩子拦截、尚未执行的调用不能留下 pending 写入，导致后续真实写入被误判并发。新用户轮开始时清理上轮内存 pending；持久化的不完整记录仍保守拒绝撤销，不伪造 after 快照或放宽外部文件冲突保护。checkpoint 状态仍归扩展独占。

本地文件路径 URI 解码须还原文件名中的 %23 等保留字符，同时保留编码的 / 和反斜杠，不把它们变成新路径层级；每次调用只解码一次，坏转义保持原值。Markdown 行号解析仍在路径解码前处理。网页 URL 路由不变。

Windows 真实复测还发现原子替换遇到短暂共享锁直接报 EPERM。仅对 Windows 的 EPERM/EACCES/EBUSY 最多重试 5 次（累计等待 620ms）；每次重试前重新检查目标哈希，等待期间发生外部修改就拒绝覆盖。继续使用同目录临时文件原子替换，不删除原文件来强行覆盖。持续占用仍报错，保留原数据。回滚也使用同一哈希保护。

验收：先拦截无开场的写入，再正常写入且可撤销；同文件跨两轮修改只撤销最近一轮，保留前一轮结果；外部冲突与真实并发写入仍拒绝。中文、空格和 # 的 Markdown 文件链接真实打开。旁路验证问答多选草稿跨任务保留、模型与思考设置重载保持。仅本地更新。

```text
tool_call → 规则/开场准入 → checkpoint.before → 原生执行 → checkpoint.after
              └─ 拦截返回（不记录写入）
href → 拆行号并解码 → 为 Markdown 安全层重新编码 href → 链接 resolver → 文件系统路径
撤销 → 哈希预检 → 原子替换 → 短暂共享锁 → 有限重试并逐次复核哈希
```
