# 搜索面板中新文件即时检索

问题：命令搜索面板只取一次全工作区文件列表，同时受 Host 的 60 秒列表缓存影响。模型写入成功后，用户再搜索新文件仍显示无结果。

规则：文件列表及缓存由 Host fileService 唯一持有；命令面板复用文件提及已有的按查询检索与无命中补扫策略。抽取共享 hook，两个入口不各自维护全仓索引。每次查询最多返回原显示上限；有缓存命中不重扫，无命中且非空查询最多补扫一次。取消、换工作区、换连接、关闭面板后忽略旧响应，不发起后续补扫；错误不自动无限重试。保留现有 UI、路径展示与打开操作。

```text
面板/文件提及 → shared query hook → fileService.searchWorkspaceFiles
                                  └─ 无命中 → 同接口 refresh=true → 当前代际展示
```

验收：预热搜索缓存→真实订阅模型创建新文件→一分钟内重新打开搜索直接命中并打开。并验证旧文件、无结果查询、查询切换、关闭重开，以及附件读入、取消与并行任务旁路。

2026-10-10：真实 Step Plan 创建文件后即时搜索并打开通过；同名不同内容附件、同路径附件换版、取消后继续对话、取消后 42 秒不出现延迟写入、两个任务并行与 Mini 数字增减均通过。取消验收以实际命令写出的启动标记为开始，不把权限等待当成进程已运行；Mini 比较新任务的增量，保留既有待处理任务。初版测试的误判与模型自行改文件名不作为产品缺陷。

## 命中旧路径的边界

文件重命名/删除后，缓存仍可能命中过期路径，因而不会触发无命中补扫。Host 对已匹配的有界候选做最多 8 路并发 stat，缺失或类型变化时只补扫一次，再过滤仍已失效的候选；不扫描所有文件来检查变化，也不增加第二份缓存。普通有效命中继续复用索引。目录重命名、文件删除与多工作区必须同样正确。读取权限错误按扫描的既有跳过语义处理，其他 IO 错误照常向调用方报告，不以无限重试掩盖。

本轮验收：两项真实文件系统回归覆盖文件改名、删除、父目录改名、条目类型变化和工作区隔离；修复前两项失败，修复后通过。真实 Step Plan 完成改名后，立即用相同关键词搜索，只显示新路径且可打开原内容。旁路验证取消提问后继续对话、两任务文字草稿与附件隔离、UTF-16LE 解码及预期退出码 13 后继续操作通过。模型给退出命令附加了 echo，外层命令正常退出；据实际输出核对退出码，不把工具 success 误判成丢失错误。

额外边界：composerDraftStore 明确只持久化文字/编辑器/模型配置，不持久化未发送附件。重启验证符合此规则，本轮仅保证任务切换期间附件隔离与恢复，不新增跨重启附件持久化方案。
