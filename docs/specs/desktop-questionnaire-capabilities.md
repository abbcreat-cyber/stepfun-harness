# 桌面问答工具能力对齐

目标：模型获得的 clarify_user 工具声明必须与桌面已有的问答能力一致，包括一组多题、单选、多选和自由文字；不能只在题干写“多选”却生成单选面板。

唯一状态仍由会话的 pending interaction Map 持有。原工具名、工具调用 ID、问题 ID、用户原始答案和取消语义保持；通过公开 extension API 接入桌面执行，不修改底座二进制。正常返回后模型只继续一次；停止/取消必须释放等待，不重复弹题。原 TUI 路径与桌面 RPC 路径按 ctx.mode 区分。

先用真实底座与本地模拟服务核对发送给模型的 schema，再用真实 Step Plan 在 UI 勾选两项并填写下一题备注，核对原生结果和最终回显。继续验证 CSV 引号/换行、表格公式缓存与预览、附件移除、运行中的排队消息删除。仅本地更新。
