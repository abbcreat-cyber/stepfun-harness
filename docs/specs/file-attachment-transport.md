# 普通文件附件接入

真实 CSV 附件测试发现：前端允许选择文件，适配层却只允许四类图片，导致消息无法发送。

附件存储仍是单一所有者：分块上传 → 完整性校验 → 会话作用域 ref → 发送时解析。保留 20MB、数量、校验和、重试及跨会话读取边界。

- 支持普通文件及空文件；图片仍验证魔数并走原生 images。非图片不冒充图片、不自动执行。
- 普通文件从已提交 ref 物化到附件目录中的稳定路径，保留安全扩展名；原文件名仅作为 JSON 数据传给模型。
- 用户正文和附件引用在 UI/台账保持原样；仅给底座的正文追加文件清单。直接发送、追加队列、插话共用同一准备路径。
- 桌面文件选择器使用协议已有的 localPath 引用；适配层校验普通文件与 20MB 上限后读取。Web/无本机路径的 File 保留原始字节上传，不再只传元信息或截断文本。附件预览仍要求引用属于当前会话消息。
- 重启后 ref 仍可解析；队列执行前重新准备附件，不依赖内存暂存。模型按用户任务通过本机工具读取文档。

验收：CSV/PDF 文件上传发送和读取、空文件、图片混合、跨会话拒绝、路径不可逃逸、图片传输回归、真实前端附件任务。

真实 Word 附件复测补充：无 localPath 的普通二进制文件必须序列化为 dataBase64；空 base64 是合法空文件。桌面显式选择的本机文件与上传 ref 共用 prepare，不增加第二条模型发送链路。
