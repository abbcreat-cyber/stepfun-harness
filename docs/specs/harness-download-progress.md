# 更新下载进度

Main 的 HarnessUpdates 是更新状态唯一所有者；窗口轮询同一快照，菜单订阅同一投影。

```text
下载命令 → preparing → 原生 download-progress → transferring → verifying → update-downloaded
                 取消 / 连续 90 秒无进度 → cancellation token → 回到可重试状态
```

- 请求发出、差分索引读取、连接等待期间没有可信百分比，展示准备下载及不定进度条，不伪造 0%。
- 收到真实进度后保留一位小数，并展示已接收/总字节与可用下载速度；总量未知时只显示已接收字节。
- 100% 传输后显示校验阶段，只有原生 update-downloaded 才允许安装。
- 取消中的迟到进度/完成事件不能恢复下载状态；下一次下载仅在上一请求收尾后开始。
- 网络无进度截止仅用于中断失去进展的下载，连续有新数据不受总时长限制；可配置较短截止用于确定性测试。
- 已完成本地修复与验收；2026-10-09 用户授权与首发提速一起发布 v1.0.4，不改变用户模型设置。
- 发现新版后，在后台下载并校验差分索引，再发布可下载状态；点击更新菜单在准备完成后才打开窗口。准备失败通过原窗口反馈，不先弹出 0% 窗口。正式下载复用已核对 URL 的索引，安装包仍由原生更新器校验。
- 2026-10-10：启动与每 30 分钟后台检查桌面更新。差分索引成功之外，还必须通过原更新器网络执行器连接安装包、收到开头的有效 EXE 字节并核对已知大小，才发布 update-available；不提前下载整个安装包。探测忽略 Range 时收到首块即中止，失败保持无更新按钮，下一次检查可重试。准备状态缓存 60 秒，过期重新验证连接。此验证证明当时可下载，不承诺之后网络永不变化；下载仍保留取消和无进度截止。

验收：准备阶段不显示 0%；0.3% 及字节数真实可见；取消/失败可重试；超时后有明确错误；真实差分下载成功并进入可安装状态，但测试不执行安装。
