# 原生编辑预览与命令组状态

前端只解释底座产生的工具参数和状态，不改变执行内容、权限或结果。复用现有 tool identity、差异生成和命令组渲染，不建立额外执行状态源。

## 文件编辑预览

Step edit_file 的参数为 path/search/replace，前端应展示待替换片段的前后差异。与旧 old_string/new_string、oldText/newText 等字段共用一个提取入口，保留原始空白和空字符串。替换为 `""` 是有效删除，不能当作字段缺失；不能把仅有 search 的检索请求当作修改。

差异卡、权限预览与代码查看器共享字段提取规则。参数只能证明修改片段，不证明整份文件内容或 replace_all 的实际匹配次数；不读取磁盘猜测执行结果。

原生 write_file/edit_file 的文件操作类型按工具契约识别，不靠英文标题的单词边界猜测。权限弹窗默认展开文件差异，展示组件必须遵循宿主的展开约定；聊天中的折叠偏好保持原样。

## 命令组状态

命令组以其子工具的真实状态派生摘要：实际运行的命令优先；无运行项且有 pendingApproval 时显示等待确认；仅有参数生成/旧 pending 时显示等待中。父组结束后立即展示最终统计，不继续展示旧命令正在运行。等待确认不播放执行动画，也不能掩盖同组另一条真正运行中的命令。

适配层必须等 `tool_execution_start` 才把工具投影为 running，不能把 `toolcall_end/message_end` 当作执行开始。参数完成但尚未被执行调度的工具保留既有 inputStreaming/前端 pending 状态及完整 input，不扩展 wire 枚举；取消时统一收口为 cancelled。前端单工具和分组共用阶段解析，明确区分输入已就绪与已开始执行。

批量工具会先依次请求预审批，因此批准第一条时必须恢复其审批前的待调度状态，不能提前标为运行中；真正进入执行的工具再次请求权限时则恢复运行态。后到的审批结果不能覆盖已经发生的执行事件。

保持已有单命令原生 PowerShell 展示、主题和中英文文案。停止/超时后的成功、失败或已停止统计仍来自底座终态。

## 验收

- search/replace、删除为空、纯空白替换、旧参数与缺失参数分别测试。
- 待审批在最后、运行项在前时优先显示真正运行项；全待审批、参数生成、父组结束及子项终态均测试。
- 真实订阅任务进行读取、编辑、删除片段与结果核对；后台界面核实审批差异可见。
- 本地部署、提交，不上传云端，不包含其他工作中的模型名称改动。
