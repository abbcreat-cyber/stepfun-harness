# 桌面输入与运行时能力提醒的顺序

真实小任务发现：直接用户指令要求回复固定短语，却被模型误认成外部提示注入。原生会话记录显示用户消息之后追加了 `ultraloop-discovery` 隐藏能力提醒；SDK 会把这种 custom message 转成 user 角色，挤占最后一条用户消息的位置。

- 用户消息正文、角色和附件保持原样，不降低网页、文件、工具输出的信任边界。
- 桌面上下文扩展只把已知运行时能力提醒（ultraloop-discovery、desktop-selected-plugin）放到本轮真实用户消息之前；保留内容及 custom 类型，不替换成系统指令。
- 不按文本、标签或关键词猜测来源；用户消息里恰有 system-reminder 等字样也不被当作运行时提醒。
- 修改仅作用于出站上下文数组，不改原始会话文件；正常 assistant/tool 消息的先后关系不变。
- 原生 CLI + 本机 HTTP 夹具验证真实线上格式的最后 user 为实际请求，能力说明仍在；真实 Step Plan 验证固定短语、普通问答及文件工具任务。

排序修正后真实复测仍出现一次固定短语误拒绝，说明不能把所有误判都归因于排序。系统级桌面输入约定需明确：用户直接给出的任务和格式要求属于用户指令；不能仅凭测试标记、固定短语或短答要求判定注入。附件、网页、工具输出和引用内容仍是数据，其他权限与安全约束保持原样。该约定不匹配某个测试词，也不自动重试拒绝的模型回复。

文件读取复测中已正确忽略外部指令，但最终多加警告违反只给数字的格式要求。明确只在异常影响结果、执行或需要用户处置时告知，成功忽略的无关指令不产生模板化附言。
