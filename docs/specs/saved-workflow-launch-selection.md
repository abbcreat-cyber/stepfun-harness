# 保存工作流启动的模型选择

复现：普通对话使用自定义配置的订阅模型，保存工作流成功；中枢“运行”创建空会话时没有携带模型，适配层退回固定 step/step-5-preview，子代理启动失败。

目标 Host 的 ModelSelectionService 独占候选与有效选型；目标工作区已有 Composer Recent 只提供最近已接受的用户意图。启动器复用普通提交的校验规则，不读取未提交正文，不从当前活动的另一个工作区借用模型，不自行挑选供应商列表第一项。

```text
运行 → 目标工作区 Recent / 目标 Host 首选模型
     → 同一 Host getView 验证 → createSession(config.modelSelection)
     → 适配层再次落定可用模型 → startSavedWorkflow → 子代理
```

- 保留 providerId、modelId 和有效推理档位；全局与项目工作流共用启动器，远程项目使用其目标服务。
- 没有可执行模型、目录读取失败或选型被删除：建会话前失败。创建后配置发生变化：start 前拒绝，不创建成功运行卡，复用既有空会话清理路径。
- 不改变权限默认值、不改保存脚本、不覆盖模型偏好、不引入第二份模型目录或队列。
- startSavedWorkflow 与其他输入命令共享 worker 准入锁；有效模型检查必须先于运行记录。
- 桌面与远端都使用同一命令协议和模型配置字段，无新增传输格式。

验证：普通订阅会话保存模板，重载后从模板卡再次启动，必须生成不同 runId，实际子代理仍使用已配置模型并返回正确结果。失败模型应在运行卡创建前拒绝。此轮仅本地提交和部署，不推送。
