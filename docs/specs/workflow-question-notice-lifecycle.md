# 工作流问题通知的时效

真实工作流测试中，主代理通过 GetWorkflowRun 发现问题并回答后，之前排队的问题通知仍在任务结束后投递，触发多余一轮检查和重复说明。

问题等待状态仅由 WorkflowQuestions 持有。通知只是该状态的派生提醒，不代表一项独立用户任务。

`子代理提问 → WorkflowQuestions.pending → 通知进入现有 InputLedger → 投递前核实问题仍待回答 → prompt`

- 内部通知携带 runId/status/questionId，随既有台账持久化；不复制问题状态。
- 通知准入前和队列真正投递前均查询工作流问题的权威状态。
- 已回答、取消或重启后不再等待的问题通知标记 cancelled；继续调度后面的正常消息，不冻结或吞掉队列。
- 未回答的问题仍通知主代理。完成通知若已被主代理通过成功的 GetWorkflowRun 回执读取，则无需再次投递；从持久化工具回执判定，不建立第二份“已读”状态。尚未读取结果的完成通知仍正常投递。
- 验收：回答早于通知准入、通知先入队后回答、仍等待的问题、取消/恢复以及无效通知之后的普通用户消息。

后续真实复测发现完成通知也存在重复投递；仅对 completed 状态抑制已读取的相同运行结果，错误及其他状态通知不受该规则影响。
