# 历史查询、文件预览、插件检查批量优化验收

## 完成的优化

- 历史列表查询：正文的 draft 校正与模型/权限元数据来自同一次读取，目标正文从每次 2 次读取降到 1 次。不缓存历史，不把整段正文额外保存在内存集合。
- 文件预览：沿用原有监听批次，明确的多文件变化附带完整路径集合；最多 64 项，未知/超限保守刷新。无关文件批量修改不会再让当前预览重新读取，目标文件、旧 Host 及未知事件仍刷新。
- 插件检查：每次 validate 从 2 次扫描降至 1 次，ok 与 diagnostics 共用该次结果；后续检查重新读取，插件修改不被缓存遮蔽。

底座、模型档位、权限与会话投递规则均未改变。FileWatchEvent 只增加可选 changedPaths，复用既有服务与 RPC 路由；新旧客户端/Host 缺字段时保持保守行为。
