# 早期开场验收（2026-10-10）

## 原因与实现

原问题轮次首 reasoning 约 1.18 秒，首正文后端记录约 62.53 秒，首响应结束约 92.86 秒。旧钩子在工具准入时检查正文，无法阻止模型在正文前长时间规划；投影又在 message_end 重算已经结束的 reasoning，把后续生成时间包含进去。没有原界面 DOM 时间，不能将后端记录当作原界面首句时间。

参考 [Codex 公开提示](https://github.com/openai/codex/blob/main/codex-rs/models-manager/prompt.md) 中工具前简短说明具体下一步的规则，并非复刻其未知内部调度。

受支持的桌面 OpenAI-compatible 推理接入在同一个 agent 轮次内，先用当前模型和账号生成一句具体计划，再按原思考配置执行主任务。开场最多一次、768 output tokens、8 秒截止；失败或空话回退主任务。关闭钩子、格式豁免、普通问候及不支持的接入维持原路径。外部未绑定原生 provider 保持直通。

这会多一次受限请求；请求耗时和额外用量不能省略不报。两次返回的 usage/cost 合并进同一 assistant 消息；超时请求若服务未返回 usage，客户端无法凭空补出实际用量。父取消信号覆盖两阶段，取消后不启动主请求。不按模型名判断，不降低主任务思考档位。

reasoning 首次结束后固定 duration；缺少 thinking_end 时，以首正文或工具块为边界。旧历史数据不重写。

## 有限真实任务

| 入口和任务 | 首句时间 | 主任务配置 | 结果 |
| --- | --- | --- | --- |
| Step 订阅账户经桌面模型配置：20 行以内 SVG 山水画 | DOM 6,461 ms；发送准入 2,153 ms；正文行到 DOM 53 ms | reasoningLevel enabled | 完整成功，保存 SVG |
| 内置 step-plan：“画一个svg山水画” | 原生正文事件 3,552 ms，非 DOM | 原生 medium，与原问题一致 | 首句后主动取消；未执行工具 |
| 用户授权的腾讯 WorkBuddy DeepSeek：读取校验文件 | DOM 3,298 ms；发送准入 2,117 ms；正文行到 DOM 66 ms | reasoningLevel max | 完整成功，校验码正确 |
| 腾讯 DeepSeek：简洁 SVG 山水画 | DOM 约 3,540 ms | reasoningLevel max | 已生成 19 行、1,864 字节的有效 SVG，随后询问是否渲染；测试停止，不计完整成功 |

腾讯测试使用用户指定的 WorkBuddy 线路，没有使用 DeepSeek 官网直连。隔离 profile 的外层 thoughtLevel 字段不代表自定义供应商实际档位；实际主请求遵循该模型的 reasoningLevel 映射。

这些是有限实测记录，不是固定延迟承诺。仅提示约束的早期尝试超过 120 秒无正文；160-token 开场上限曾因为服务内部推理消耗而截断无正文，后续调整上限。保留失败尝试，不以成功样本掩盖服务波动。

## 第二模型暴露的工具兼容问题

腾讯网关在 arguments 增量之后重发完整参数快照。校验器仅对与已收集完整对象 JSON 逐字一致的快照去重；冲突对象、残片、超限数据仍拒绝。修复位于通用参数完整性层，不修改外部网关，不按供应商名字放行。

## 回归与交付边界

覆盖两阶段事件索引、usage 合并、超时、父取消、开关、格式豁免、无意义开场、原生绑定与未绑定供应商、工具参数完整性、reasoning 结束边界及流投影。真实任务通过隔离桌面实例的前端发送并读取 DOM；内置 step-plan 补测只测原生事件，因此与 DOM 结果分开列出。

最终回归 62 项通过；typecheck 通过，Lint 77 条基线 warnings、0 errors，architecture 检查 0 violations。用户随后明确授权云端发布，此修复随 v1.0.9 的源码与 Windows 安装包统一交付。
