## 发现与修复

会话管理测试意外暴露：正常用户要求“这是临时测试会话，只回答指定短语”，被模型误判为提示注入。

原生 CLI + 本机 HTTP 夹具确认：底座自动生成的 ultraloop-discovery 隐藏提醒被转换为 user，排在真实请求之后。适配层现在按 custom 类型识别已知运行时能力提醒，将其放到本轮用户请求前；保留内容、原始历史和工具顺序，用户正文不改写，也不按内容中的标签猜测消息来源。插件能力事实仍可被模型读取。

排序修正后有一次同类误拒绝，说明排序不是全部原因。统一系统输入规则进一步明确直接用户任务、格式要求与外部数据的区别。文件数据边界复测曾得到正确总数但附带多余警告；随后明确只在异常影响结果、执行或需要用户处置时说明，保持用户要求的最终格式。最终真实复测通过，不通过替换测试提示或过滤模型回复伪造结果。

后台驱动也修正了“重命名任务”和带快捷键标记的删除确认按钮定位；这些选择器失败保留在本机记录，不归为产品缺陷。

改动位于桌面适配扩展，不修改底座可执行文件或关闭原有权限边界。未推送、未发布。

验证：17 项相关回归全部通过（包含本机真实 Step CLI 和本地 HTTP 请求夹具，未跳过）；typecheck、架构检查通过，lint 为 0 error、77 warning。正式本机实例已后台重启，输入框加载正常，两份上下文运行模块与源码哈希一致。
