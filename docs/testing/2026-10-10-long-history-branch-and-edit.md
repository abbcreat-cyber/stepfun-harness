# 长历史恢复、编辑与重试验收

## 发现与修正

沿前端历史操作到 Step Code 原生分支的路径检查，确认两处问题位于 adapter 的 history-controls。

1. `activeEntries` 用数组 includes 检测环，每回溯一步扫描已访问前缀。改为 Set，保持按 entry 对象判断、原顺序、旁支过滤、重复 ID 和缺链拒绝语义。
2. 编辑/重试在原生 fork 后用展开参数求所有行号的最大值。20 万行测试在旧实现确实抛 `RangeError: Maximum call stack size exceeded`；改为逐行 reduce，不受函数参数数量限制，原高水位继续保留。

底座 fork、前端 target/revision、发送接口、模型配置和历史回滚规则未变化。
