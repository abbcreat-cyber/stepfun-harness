# 速度专项：基线与浏览器启动往返优化

基线 `1de0047`。使用同一 Windows 主机、同一 Step Plan 订阅模型和思考设置，隔离 QA profile；后台 DOM、Node RPC 边界时间戳与真实页面服务器记录。未调用其他 API 账户或使用虚拟机。

## 分层结果

- 两轮普通对话中，已启动会话的输入进入消息界面约 84–110ms；第二轮从点击发送到首次 prompt RPC 约 50–57ms。相关 RPC 往返合计约 8–11ms。
- 新会话约 2.2–2.7 秒后显示输入；底座 `start/get_commands` 约 1.8–2 秒。没有把这一冷启动描述成已优化。
- 配置检查的热态采样很短：插件签名约 2.8–3.4ms，扩展签名约 0.2–1.3ms，未为此引入会过期的配置缓存。
- 一个普通 Node 命令本地执行约 369ms；整项任务约 11 秒，包含开场规则处理及模型多轮响应。不能将全部任务时间归因于工具。

## 保留的优化

原浏览器指引容易让模型分别请求文档、受控标签、用户标签，每次工具回执后再次推理。新指引将首次只读准备合并，仍在模型看到列表后才执行目标操作；旧官方安装按已知哈希迁移，用户自改指引保留。

相同的简单网页校验码读取任务，各运行两次；每次实际页面加载一次，结果正确。

| 样本 | Node 调用数 | 本地工具执行合计 | 任务总时间 |
| --- | ---: | ---: | ---: |
| 优化前 A | 5 | 2,540ms | 56,761ms |
| 优化前 B | 3 | 1,282ms | 20,758ms |
| 优化后 A | 2 | 978ms | 16,764ms |
| 优化后 B | 2 | 931ms | 24,020ms |

可确认的收益是启动只读往返减少 1–3 次，以及这些样本中的本地工具开销降低；样本量有限且模型耗时波动大，不宣称所有任务固定加速某个百分比。

会话证据：优化前 `step-session_460fa99c-fa4c-4f03-a4ea-efded7f008d6`、`step-session_9559d021-ded2-4e36-9e84-7faecc7bb942`；优化后 `step-session_50376653-ec93-437b-a0e2-cba4cb025198`、`step-session_087a6a9e-cf04-4cba-bab3-23d061b6dd73`。

- 自动测试覆盖首次示例的只读调用顺序、完整输出、旧版迁移、幂等、命名空间、自改指引保留、第三方声明及插件刷新，3 项通过。
