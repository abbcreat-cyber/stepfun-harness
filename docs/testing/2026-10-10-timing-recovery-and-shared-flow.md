# 历史计时与共享连接优化验收

## 修正范围

仅改 Harness adapter，未改 Step Code 底座、模型或思考档位。

1. 历史计时恢复不再针对每条消息扫描并排序全部事件，改为一次性的 provider/model/250ms 时间桶。已完整恢复的热会话不构建索引。同距离顺序、误差窗口、坏时长、事件去重与工具计时保持原规则。
2. 两个会话共用连接时，取消其中一个订阅不再提前删除连接流控状态；所有 worker 都无该连接订阅后才回收。取消失败不删除订阅路由，允许重试。

## 复现和测量

旧实现在新增测试中出现 3 项预期失败：saturated/closed 连接都被提前清除；500 条历史消息调用了 125,750 次 Date.parse。

在同一 2,000 条消息、2,000 条计时事件受控样本上，交替运行前后实现 5 次：

| 指标 | 之前 | 之后 |
| --- | --- | --- |
| 局部计时恢复耗时 | 239.0–247.6ms | 8.9–10.3ms |
| Date.parse 调用次数 | 2,003,000 | 4,000 |

每轮序列化统计完全一致。此数据只覆盖内存中计时匹配，不包括读盘、网络、模型回答或 UI 整体耗时。150 组确定性随机差分及显式同距/250ms 边界/坏值场景也通过；已恢复统计重复调用保持不变，不额外扫描计时事件。
