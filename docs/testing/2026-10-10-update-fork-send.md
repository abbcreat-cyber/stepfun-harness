# 自动更新、消息分叉与发送延迟验收

## 发送

真实订阅小任务在隔离桌面 profile 复现：重启后已有会话第一次发送，编辑器等待 3,987 ms 才清空；下一次 177 ms。诊断将约 1,900 ms 定位到原生启动的 get_commands，约 1,450 ms 定位到紧随其后的 switch_session。配置和权限准备数十毫秒、prompt ACK 数毫秒，故不能归咎于开场钩子或模型首句。

改为展示会话时恢复 worker，冷启动通过 --session 直接加载目标历史。前端沿用原发送草稿快照和预览，覆盖已有空闲会话，在权威确认前明确标为“正在发送”，不制造成功 ACK。

修改后同类实测编辑器清空 305 ms，后续 15 ms；这是有限 UI 反馈测量，不代表模型输出耗时或固定网络延迟保证。直接原生启动测试验证没有 switch_session 也能读取原历史。发送前置检查和模型映射回归保留。

故障注入发现 Lexical clear 的重复空文本回调被当作新编辑，导致失败草稿不能恢复；修正为相同正文不推进编辑修订号。实际界面验证拒绝时恢复原稿、等待期间的新输入不被覆盖、等待预览移除。故障注入仅在隔离候选副本，正式产物不含探针。

## 分叉

此前仅编辑/重试复用了 Step 原生 fork，forkAssistant 未接通，前端因此不显示按钮。现在使用原操作栏、CAS 命令、worker 串行路径和独立原生文件，不改原会话。

真实 Step Plan 界面测试：父会话两轮口令，从第一轮回复点击分叉，约 3,207 ms 创建子会话；只保留第一轮，第二轮没有泄漏，子会话续聊正确返回第一轮口令。父会话原生文件逐字未变。

真实底座配本地模型响应覆盖最新 clone、较早 fork、父子独立续聊、重复正文锚点与文档附件复制/路径重映射；故障测试覆盖取消、索引失败与无效目标。分叉不复制待执行队列，也不允许对子会话继承的历史执行原会话文件撤销。

性能处理：线性构建原生与投影索引，复用已绑定用户 entry；只复制目标前缀和被引用附件；前端合并正在执行的点击并显示禁用状态，命令重放复用既有幂等链。没有通过跳过原生恢复或模型参数校验来提速。

## 更新

真实生产 renderer 的中文/英文、浅色/深色四种确认框均检查无越界、按钮同排；取消不触发下载，确认后等待任务转空闲并自动进入安装，不要求第二次确认。

独立 NSIS 验收应用使用同一 HarnessUpdates 控制器与 electron-updater：真实本地 HTTP 下载、SHA-512 校验、/S 与 --force-run 启动安装器一次，安装后的 1.0.10 验收程序自动运行。使用独立应用身份与 D 盘安装路径，没有覆盖正式安装或使用虚拟机。一次重跑碰到验收卸载器异步收尾竞态；等卸载完成后以全新缓存重测通过。该测试证明原生安装协议链路，完整产品包另做版本与启动验收。
