# 原生工具接入调查

本轮使用随包 Step 0.1.3 的真实 RPC 与扩展工具目录核实，未调用模型完成目录调查。范围是基础工具及已启用的 PowerShell，不包含需要服务连接的全部插件工具。

当前目录注册 33 个基础工具，活动集 26 个。未活动的 7 个均有当前 Step 产品工具对应能力：

| 未活动底层工具 | 当前已启用入口 | 能力 |
| --- | --- | --- |
| read | read_file | 文件与图片读取 |
| write | write_file | 文件写入 |
| edit | edit_file | 文本替换 |
| grep | search_files | 内容检索 |
| find | find_files | 文件查找 |
| ls | list_directory | 目录查看 |
| bash | run_command | Shell 执行及后台任务 |

这些入口均在真实底座工具表中注册，不是桌面桥接临时构造的替代执行器。两套工具的参数和细节并不完全相同，因此不能仅凭名称互换。PowerShell 与 Bash 是不同解释器，前次接入补足了 Windows 独立执行能力；其余七项不需要重复打开。

底座随包 `docs/mcp-catalog.md` 说明 find_tools 只搜索活动工具，因此“已注册”与“模型能发现”必须分别核对。后续底座适配按注册、活动、模型发现、权限、执行、前端呈现逐项验证，不能只看工具存在。

本轮还确认原生审批预览未关联命令参数，且多工具时按最后一行锚定会错配。已通过完整调用 ID 关联，并保留找不到记录时的原文回退；相应回归包含错序审批、未匹配、批准、拒绝及交互清理。
